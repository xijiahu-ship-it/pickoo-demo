    这份 Demo 怎么用

    目的：让产品和研发在评审时一眼知道「点了这里会去哪个页面」。页面图取自设计稿 Okiee 官网 · 11.2 定稿，热区和跳转关系是按设计稿里的 frame 命名（弹窗 / 点击唤起chat / 展开全屏 / 跳转到chat…）和分区标题整理出来的。

    操作

    • 页面图上方一行「本页待确认」列出这个页面涉及的评审问题（Q1–Q11），点一下展开全文、责任人和相关页面，同时在图上用红框高亮这条问题涉及的位置。带「开会明确」标签的是交互稿里找不到答案、需要会上定的。
    • 页面图默认不画框，鼠标悬停任意可点位置会显示去向。右上角按钮可切到「只看待确认」（橙色框标出和问题相关的位置）或「全部热区」（紫色虚线）。
    • 图下方是评论区：写名字和意见，按页面保存在你自己的浏览器里。看完后点「复制全部评论」或「下载 .md」，把汇总发到群里。
    • 黄色框是外链（Chrome 商店、商家站 Buy Now），灰色框是只做状态说明的元素（置灰按钮、toast 等），点了不会跳页。
    • ← 或「返回」回到上一个页面；Esc 回首页。每个页面都有独立链接（地址栏 #），可以直接发给别人定位到某个状态。
    • 「流程总览」把每个分区的页面按顺序摆开，用来对整条链路。

    覆盖范围与假设

    • 共 55 张页面图，覆盖 Figma 该页全部桌面端 frame（1920 宽）；两张 393×853 的 Migoo 移动端卡片是参考图，未收录。
    • 「已登录首页」是用顶栏组件（头像态）与默认首页合成的，Figma 里没有单独这一帧。
    • 设计稿没有连线的跳转（比如商品卡 → PDP、心形 → Favorites、Adjust with Okiee → 对话内编辑），按分区标题和同类产品惯例推断，标注里写了「推断」，评审时重点确认这些。
